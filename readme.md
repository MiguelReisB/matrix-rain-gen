<h1 align="center"> A new way for styling READMEs</h1>

<h3 align="center">Generate a <b>transparent, seamlessly looping animated WebP</b> of Matrix-style falling characters to style your GitHub's READMEs in less than 1 minute.
</h3>
<br>

#### GitHub strips `<canvas>` (and most of CSS Styles) and JavaScript from READMEs, so the effect can't run live there. This tool renders it frame by frame in a headless browser and packs the frames into an animated WebP that works in any HTML `<img>` tag and MarkDown `![]()` , including your GitHub profile README. [See an example used on my profile](https://github.com/MiguelReisB) and the one that is generated by default with the first code run:

![Matrix Rain Example](webpExamples/defaultBlueMatrixRain.webp)

## How it works

1. `script.js` draws the rain on `rain.html`'s `<canvas>`. Each frame is a pure function of its index, so the animation is deterministic and a given seed always gives the same result.
2. `capture.py` opens the page in headless Chromium *(Playwright)*, draws each frame, and takes a transparent screenshot of it. Frames are captured in parallel, one browser per CPU core **(if it wasn't used, depending on the size and duration of the animation, it'd take something around TEN (10) MINUTES to generate one webp file).**
3. *Pillow* assembles the frames into an animated WebP with a full alpha channel.

The loop is seamless because no drop starts unless it can finish before the rain ends. The last frames are empty, which acts as the "cut" between the end and the start.

## System Requirements

- Python 3.9+
- Git (of course)
- About 1 GB of free RAM for the default settings (frames are held in memory)

## Getting started

### 1. Clone this repo, and proceed with the next steps in the same terminal

```bash
git clone https://github.com/MiguelReisB/matrix-rain-gen.git
cd matrix-rain-gen
```

### 2. Create and activate a virtual environment

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows (PowerShell):

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

Windows (CMD):

```bat
py -m venv .venv
.venv\Scripts\activate.bat
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
playwright install chromium
```

`playwright install chromium` downloads the browser used for rendering. It is stored outside the virtual environment, so it is only needed once per machine.
On a headless Linux server, use `playwright install --with-deps chromium` instead.

### 4. Generate the WebP

```bash
python capture.py
```

- If it didn't work:
```bash
python3 capture.py
```

The result is saved as `matrixRain.webp` in the project folder.

### 5. Use it in a README (put inside the project's folder, as an separated asset)

```html
<img src="path/to/your/matrixRain.webp" alt="Matrix Rain Animation" width="100%">
```

```md
![Matrix Rain Animation](path/to/your/matrixRain.webp)
```

> It is padronized to 900 x 600 (Width x Height) dimensions because of GitHub's "supporting" (or limiting) an image's width in READMEs only up to 900px. The height you can change as you wish.

## Customize as you want

Edit the constants of `script.js` and `capture.py`, then run `python capture.py` (or `python3 capture.py`) again.

### In `script.js`

| Setting | Default | What changes |
|---|---|---|
| `WIDTH`, `HEIGHT` | `900`, `600` | Canvas size in pixels. Must match the `width`/`height` attributes of the `<canvas>` tag **and** `WIDTH`/`HEIGHT` in `capture.py`. |
| `FONT_SIZE` | `33` | Character size in pixels. Larger means fewer, bigger columns. |
| `PATH_SIZE` | `14` | Trail length in characters. Longer trails fade out more slowly. |
| `COLOR` | `'30, 144, 255'` | RGB color of the characters (`R, G, B`). `'0, 255, 70'` gives the classic green. |
| `CHARACTERS` | katakana + digits + letters + symbols | Pool of characters drawn at random. Replace it with any string and even emojis. |
| `FPS` | `20` | Frames per second. Higher is smoother but gives more frames, so generation is slower and the file is bigger. |
| `SECONDS_RAIN` | `10` | Duration of the rain. This is most of the animation length. |
| `SECONDS_EMPTY` | `0.1` | Empty time at the end, used as the loop cut. Increase it for a longer pause before restarting. |
| `20 / FPS` (`velForFrame`) | `20` rows/s | Fall speed. The `20` is rows per second: larger is faster. |
| Gaps in `cron` (`FPS * 1.7`) | `1.7 s` | Maximum random pause between two drops in the same column. Lower means denser rain. |
| First start (`FPS * 4`) | `4 s` | Maximum delay before a column's first drop. Lower means the screen fills faster. |
| `CSS mask-image` | `black 20%` | Where the bottom fade starts. `black 60%` fades later, and removing the mask gives a hard edge. |

Total frames = `FPS × (SECONDS_RAIN + SECONDS_EMPTY)`, and the total duration of the file is `SECONDS_RAIN + SECONDS_EMPTY`.

### In `capture.py`

| Setting | Default | What changes |
|---|---|---|
| `WIDTH`, `HEIGHT` | `900`, `600` | Screenshot size. Must match `rain.html` and `script.js`. |
| `SEED` | `1` | Different seeds give different rain patterns. The same seed always reproduces the same file. |
| `WORKERS` | CPU count | Number of parallel browsers. Lower it if you run out of RAM. |
| `quality` | `90` | WebP quality (0-100). Lower gives a smaller file with more compression artifacts. |
| `alpha_quality` | `100` | Quality of the transparency channel. Keep at 100 to preserve smooth character edges. |
| `method` | `4` | Encoder effort (0-6). `6` gives the smallest file but is much slower. `0` is the fastest, useful while testing. |
| `exact` | `False` | When `True`, keeps color data under fully transparent pixels. It is not needed here. |

> **Tip:** while adjusting colors and sizes, use `SECONDS_RAIN = 2`, a lower `FPS` and `method = 0`. When you are happy with the result, restore the final values.

## Problems you may stumble across and how to fix it

- **`Executable doesn't exist` from Playwright:** run `playwright install chromium` inside the activated virtual environment.
- **Out of memory:** lower `WORKERS`, `FPS` or the canvas size.
- **`range()` error about a float:** make sure `FRAMES_TOTAL` is wrapped in `Math.round(...)` in `rain.html`.
- **Generation is slow:** lower `method` in `capture.py`. Capture time and encoding time are both printed at the end, so you can see which one dominates.
- **The animation doesn't loop cleanly:** keep `SECONDS_EMPTY` above zero.
